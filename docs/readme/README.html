Design Goals

설계 목표 — 분리하고, 재사용한다

화면이 커져도 관리할 수 있도록 세 가지 기준을 먼저 정하고 구조를 잡았습니다.

01

데이터와 화면의 분리

상품 이름·가격·이미지를 HTML에 직접 쓰지 않고 JSON으로 분리했습니다. 상품이 바뀌면 JSON만 고치면 됩니다.

  • 섹션별 JSON 6개 + 상세 JSON 1개
  • 기능별 01~06_fetch_*.js가 읽어서 카드 생성
  • 가격·할인·평점 등 없는 값은 화면에서 자동 생략
json/*.json
  └▶ js/0N_fetch_*.js
       └▶ <article> 카드
5 + 5 + 5 + 5 + 3 + 10 = 33
02

공통과 페이지별 스타일 분리

모든 페이지에 들어갈 요소와 한 페이지에만 쓰는 요소를 나눠, 새 페이지를 추가해도 공통 부분은 다시 만들지 않게 했습니다.

  • reset.css 브라우저 기본값 초기화
  • common.css 헤더 · 푸터 · 변수
  • main.css / sub.css 페이지 전용
index.html  reset + common + main
sub.html    reset + common + sub

// js/01_fetch_client.js (일부)
export function loadClientProducts() {
  fetch("./json/client_products.json")
    .then((res) => res.json())
    .then((data) => {
      grid.innerHTML = data.items.map((item) => {
        const badge = item.badge ? `<span …>` : "";
        return `<article class="client-card"> … </article>`;
      }).join("");
    });
}

Decisions

기술적 의사결정

선택한 방식과 검토한 대안, 그렇게 정한 이유를 정리했습니다.

항목채택검토 대안이유
데이터 저장JSON 파일 + fetchHTML에 직접 작성 / DB읽기 전용이고 갱신이 적어 DB는 과하고, HTML 직접 작성은 수정할 곳이 너무 많아집니다.
렌더링 코드 분리섹션별 export function하나의 큰 스크립트import되는 순간 실행되는 것을 막고, main.js에서 실행 시점을 한 곳에서 제어합니다.
스타일 분리reset · common · main · sub섹션마다 CSS 파일파일이 많아 관리가 어려웠고, 서브 페이지 추가를 고려해 “공통 / 페이지별”로 나눴습니다.
상세 콘텐츠블록 타입별 템플릿상세 HTML 직접 작성상품이 늘어도 같은 코드로 다른 내용을 그릴 수 있습니다.
없는 값 처리값이 있을 때만 태그 생성빈 칸으로 표시할인·평점이 없는 상품도 레이아웃이 깨지지 않고 자연스럽게 보입니다.
페이지 이동<a href target="_self">onclick 스크립트 이동링크 형태를 유지해야 검색·키보드 이동·새 탭 열기가 기본으로 동작합니다.
배포GitHub Pages별도 서버 호스팅빌드 없이 저장소를 그대로 올릴 수 있어 포트폴리오 링크로 공유하기 쉽습니다.

Roadmap

향후 계획 — 백엔드로 확장

지금의 JSON 구조를 그대로 DB로 옮기고, 화면은 거의 바꾸지 않는 방향으로 진행합니다.

구조

브라우저 (현재 사이트)
   │  fetch("/api/...")
   ▼
FastAPI 서버 ──▶ Supabase (PostgreSQL)
   │              products · sections
   │              section_products · product_details
   └────────────▶ OpenAI (챗봇, 버튼을 눌렀을 때만)

같은 상품이 여러 섹션에 나와도 상품은 1줄만 두고 섹션과는 연결 표로 묶습니다.

단계

  • 1. Supabase에 표 4개 생성, 기존 JSON 이전
  • 2. 섹션별 목록 · 상세 · 검색 API
  • 3. 화면이 JSON 대신 API를 읽도록 변경, 카드마다 자기 상세로 이동
  • 4. 쇼핑몰 안내 챗봇 (문서에 없는 내용은 “확인되지 않습니다”)
  • 5. 서버 배포 · 챗봇 사용 횟수 제한 · 키는 서버에만 보관
  • 6. 이후 로그인 · 장바구니
