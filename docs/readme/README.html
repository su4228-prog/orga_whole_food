설계 목표 — 화면을 유지하며 서버로 확장

기존 렌더링 코드를 살리고 데이터 공급원만 JSON에서 API와 DB로 바꿨습니다.

01

API 우선, JSON 대체

화면은 같은 데이터 모양을 사용합니다. Render에서는 API를 읽고, 서버가 없으면 기존 JSON으로 자동 전환합니다.

  • api.js가 실행 환경에 맞는 주소 선택
  • API 오류 시 섹션 JSON으로 대체
  • GitHub Pages 정적 버전도 계속 동작
Render  /api/sections/{key}
   └▶ 카드 렌더링
정적    json/*.json
   └▶ 같은 카드 렌더링
02

중복 없는 DB 구조

상품은 한 번만 저장하고 여러 섹션에는 연결 정보만 둡니다. 가격이나 설명을 한 곳에서 수정할 수 있습니다.

  • products 상품 30개
  • sections 섹션 6개
  • section_products 카드 연결 33개
products 1 ── N section_products
sections 1 ── N section_products
products 1 ── 1 product_details
03

키와 비용 보호

브라우저에는 비밀 키를 보내지 않습니다. 서버가 외부 서비스와 통신하고 상담봇 호출 횟수도 먼저 제한합니다.

Architecture · API First

API 우선 · JSON 대체 구조

같은 화면 코드가 Render에서는 API를, GitHub Pages에서는 JSON을 읽습니다.

// js/api.js
export async function loadSection(key, fallback) {
  const base = apiBase();
  if (base !== null) {
    try { return await getJson(
      `${base}/api/sections/${key}`);
    } catch { console.warn("JSON으로 대체"); }
  }
  return getJson(fallback);
}
// 실행 환경별 데이터 흐름

로컬 실행과 Render 배포

로컬에서는 backend 폴더에서 실행하고, Render에서는 저장소 루트 기준 명령을 사용합니다.

01

로컬 서버 — PowerShell

# 저장소 복제
git clone https://github.com/su4228-prog/orga_whole_food.git
cd orga_whole_food\backend

python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env

.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8000

.env에는 본인 환경의 값을 직접 입력하고 GitHub에는 올리지 않습니다.
